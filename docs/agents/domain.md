# 领域文档

工程类 skill 在探索代码库时，应如何获取本项目的领域文档。

## 开始探索前，先读这些

- **`CONTEXT.md`**（项目根目录），或
- **`CONTEXT-MAP.md`**（如果存在）— 它指向多个上下文各自的 `CONTEXT.md`。阅读与当前任务相关的每一份。
- **`docs/adr/`** — 阅读与你即将工作的领域相关的 ADR。多上下文项目中，还需检查 `src/<上下文>/docs/adr/` 下的上下文级决策。

若上述文件不存在，**静默跳过**。不要提示缺失，也不要建议立即创建。生产者 skill（`/grill-with-docs`）会在术语或决策真正敲定时，按需创建。

## 文件结构

单上下文项目（大多数项目适用）：

```
/
├── CONTEXT.md
├── docs/adr/
│   ├── 0001-event-sourced-orders.md
│   └── 0002-postgres-for-write-model.md
└── src/
```

多上下文项目（根目录存在 `CONTEXT-MAP.md` 时）：

```
/
├── CONTEXT-MAP.md
├── docs/adr/                          ← 系统级决策
└── src/
    ├── ordering/
    │   ├── CONTEXT.md
    │   └── docs/adr/                  ← 上下文级决策
    └── billing/
        ├── CONTEXT.md
        └── docs/adr/
```

## 使用词汇表的术语

当你的输出中需要命名一个领域概念（Issue 标题、重构提案、假设、测试名称），请使用 `CONTEXT.md` 中定义的术语。不要滑向词汇表明确避免的同义词。

如果你需要的概念尚未出现在词汇表中，这是一个信号——要么你正在发明项目中不存在的术语（需要三思），要么确实存在空白（记录下来，供 `/grill-with-docs` 处理）。

## 标记 ADR 冲突

如果你的输出与既有 ADR 存在冲突，应明确指出来，而非悄悄覆盖：

> _与 ADR-0007（事件溯源订单）存在冲突——但值得重新讨论，因为……_
