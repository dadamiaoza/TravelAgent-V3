# TravelAgent V3 MVP v1 正式方案

> 目标：先做一条稳定可用的最小闭环，不再追大而全。
> 当前 C1 分支建议合并后，以本 MVP 作为后续迭代基线。

---

## 1. MVP 目标

让用户能够：

```text
创建行程
→ 增删 Day
→ 增删地点
→ 通过 AI 对话调整行程
→ 重新计算路线
→ 在地图上看到点位和路线（真实优先，示意兜底）
→ 数据持久化
```

核心产品原则：

```text
AI 建议 → 用户确认 → 写入行程
用户手动编辑 > AI 自动建议
```

---

## 2. 范围

### 2.1 必须包含

| 功能 | 说明 |
|---|---|
| 创建行程 | 输入目的地/日期/人数/偏好，生成初始行程 |
| 增删 Day | 自动重排编号和日期 |
| 增删地点 | 支持新增/删除单个景点 |
| 编辑地点 | 名称/时间/备注 |
| 同天排序 | 调整同一 Day 内顺序 |
| 重新计算路线 | 重新计算交通时间与路线 |
| AI 对话 | 带行程上下文，返回结构化建议 |
| 建议采纳 | add / update / delete / reorder 建议可采纳 |
| 地图展示 | 点位编号、景区颜色、真实路线优先、示意线兜底 |
| 数据一致性 | 编辑快照 + 防抖同步 + setQueryData 静默更新 |

### 2.2 不包含（MVP 之后）

- SSE 流式回复
- 长短期记忆
- 用户注册登录 / 数据隔离
- 地图 Provider 替换
- PDF / 图片攻略解析
- AI 自动执行（无需用户确认）
- 版本快照 / 回滚
- 真正的拖拽排序

## 3. 用户主流程

```text
首页输入旅行想法
  ↓
优化提示词
  ↓
确认并生成行程
  ↓
行程详情页
  ├── 地图 + 列表
  ├── Day 操作：新增一天 / 删除这天 / 新增地点 / 删除地点 / 重新计算路线
  └── 右侧 AI 对话
      ├── 描述修改意图
      ├── 得到建议卡片
      ├── 采纳 / 忽略
      └── 自动刷新地图和列表
```

## 4. 验收标准

### 功能验收

- [ ] 能创建 2-3 日行程
- [ ] 能新增/删除 Day，编号和日期连续
- [ ] 能新增/删除地点，并自动重算当天路线
- [ ] AI 建议“已采纳”后，行程确实发生变化
- [ ] 重新计算路线能在可接受时间内返回
- [ ] 地图显示点位编号和路线
- [ ] 真实路线缺失时，明确显示为示意线，不伪装真实

### 质量验收

- [ ] `pytest -m "not agent"` 全绿
- [ ] 前端 `tsc` 通过
- [ ] 浏览器控制台无报错
- [ ] 单天/多天行程均可操作

## 5. 关键技术架构

```text
前端
  React Query（读）
  Zustand dirtyTrip（写/编辑快照）
  ChatPanel（对话 + 建议卡）
  TripMap（地图渲染，MapProvider 抽象预留）

后端
  HTTP Controller（trips.py）
  trip_editor（应用服务/唯一入口）
  Ports & Adapters（RoutePlanner / Scheduler / Geocoder / Generator）
  agents/（LLM、路线优化、攻略解析）
  PostgreSQL（持久化）
```

## 6. 已知问题与处理策略

| 问题 | 策略 |
|---|---|
| 高德路线请求慢 | 只计算相邻路段，降低请求量 |
| 高德路线失败 | 降级为估算/示意线 |
| AI 建议重复地点 | 同一天防重复，跨天允许同名 |
| AI 建议未生效 | 采纳后自动重算路线并回写最新数据 |
| 地图坐标/路线不真实 | 明确区分真实路线和示意线，后续做 Provider 抽象 |
| 行程列表与地图同步 | 使用同一份 dirtyTrip store |

## 6.1 基础设施持久化（已落地）

- `amap_cache` 表：持久化高德地理编码/方向结果
- `generation_jobs` 表：持久化生成任务与进度
- 进度接口改为从 `generation_jobs` 读取，不再依赖内存
- 为后续用户隔离预留依据（任务/行程均可关联 user_id）
