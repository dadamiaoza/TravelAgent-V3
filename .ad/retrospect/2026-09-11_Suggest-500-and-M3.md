## 1. 提示词优化 500：不是 JSON，是 HTTP 解压

**现象**

首页点「优化提示词」，前端显示「提示词优化失败」。后端：

```
POST /api/v1/trips/suggest  500 Internal Server Error
TypeError: process() takes no keyword arguments
  httpx2/_decoders.py  BrotliDecoder.decode
openai.APIConnectionError: Connection error.
langchain_openai ... OpenAIConnectionError: Connection error.
```

短句探测有时能通，真实 suggest 长响应必挂。看起来像「连不上 MiniMax」，其实请求已经回来了。

**原因**

1. 本机 `openai` 3.x 默认走 `httpx2`（不是经典 `httpx`）。
2. MiniMax / CDN 对较大 JSON 常用 `Content-Encoding: br`。
3. `httpx2` 的 BrotliDecoder 调用 `brotli.Decompressor.process(data, output_buffer_limit=...)`。
4. Anaconda 的 `brotli` 1.0.9 只接受位置参数 `process(string)`，关键字参数直接 `TypeError`。
5. openai SDK 把解码失败包装成 `APIConnectionError`，FastAPI 未捕获 → 500。

langchain-openai 还会注入自定义 transport（TCP keepalive），日志里会提示关掉了系统代理自动检测。那是另一条干扰；这次崩溃发生在**已经读到响应体之后**。

**方案**

所有 MiniMax 调用改走 `app.core.llm.chat_model()`：

- 用 openai `DefaultHttpxClient` / `DefaultAsyncHttpxClient`
- 请求头 `Accept-Encoding: gzip, deflate`，不再声明 `br`
- `/trips/suggest` 把连接/解码失败改成 502，并把 `detail` 传回前端

不要「升级 brotli」当唯一修复：那依赖本机 site-packages，换机器还会炸。HTTP 客户端必须在应用层钉死。

**不要做的**

- 不要全局开 MiniMax `extra_body.reasoning_split=True`。M3 可以把思考放到 `reasoning_details`，LangChain 多轮 tool 回写历史时会丢掉该字段，Agent 循环会变差。JSON 工作流继续剥 `<think>...</think>`。

**验证**

修复后 `POST /api/v1/trips/suggest` 返回 200，能解析出 destination / city / dates。

## 2. 全面升级 MiniMax M3

**范围**（当前默认，不是改历史复盘里「当时用的是 M2.7」）

| 位置 | 变更 |
|------|------|
| `app.core.config.Settings.llm_model` | 默认 `MiniMax-M3` |
| `src/backend/.env` / `.env.example` | `LLM_MODEL=MiniMax-M3` |
| `chat_model()` | 读 `settings.llm_model`，所有 Agent / Workflow 共用 |
| `CLAUDE.md` / `README.md` / `docs/plans/decisions.md` | 对外技术栈改为 M3 |

模型 ID 以 MiniMax OpenAI 兼容文档为准：`MiniMax-M3`（中国区 base URL 仍是 `https://api.minimaxi.com/v1`）。

M3 默认开启 thinking；`content` 里仍可能带 `<think>`。既有清洗逻辑保留。

**回滚**

`.env` 里把 `LLM_MODEL` 改回 `MiniMax-M2.7` 即可，不必改代码。HTTP 工厂仍要留着。
