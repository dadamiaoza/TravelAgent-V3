# AI 旅行规划助手 V2：需求文档

> V2 定位：从"能抄"到"抄得好"——更智能的攻略获取、更完整的解析、更可靠的记忆。
> V1 基线已完成（S0-S7），本文档定义下一轮增强迭代的需求与范围。

---

## 1. V2 核心命题

V1 实现了"抄作业型 AI 行程编辑器"的最小闭环。V2 解决三个遗留问题：

| # | 问题 | V1 状态 | V2 目标 |
|---|------|--------|--------|
| 1 | 攻略获取靠手动粘贴 | 用户自己找攻略、粘贴文本 | 一句话搜索 → 自动抓取 → 解析 |
| 2 | 解析只出名称 | 输出 `["西湖", "灵隐寺"]` | 输出时长、最佳时段、费用等结构化字段 |
| 3 | Agent 多轮失忆 | 只能读历史消息推断当前状态 | 结构化状态注入 + 上下文修剪 |

---

## 2. V2 用户场景

### 场景 1：搜索 + 抓取（S11）

```
用户："帮我搜杭州三天两夜攻略"
  → Agent 调 Tavily 搜索小红书/马蜂窝
  → 返回链接列表，用户确认
  → Agent 调 Firecrawl 逐条抓取 → Markdown
  → guide_parser 解析 → 候选列表
  → 用户勾选 → 生成行程
```

### 场景 2：手动粘贴增强（S9）

```
用户：粘贴一篇小红书攻略文本
  → guide_parser 解析
  → 输出：
      西湖    | 建议3-4小时 | 早晨去人少 | —
      灵隐寺  | 建议2小时   | 上午       | 门票75
      雷峰塔  | 建议1.5小时 | 傍晚看日落 | 门票40
  → 用户看到时长+时段+费用，做更好的选择
```

### 场景 3：多源交叉验证（S10）

```
用户：粘贴 3 篇不同攻略
  → 分别解析 → 合并去重
  → 西湖（3篇提到，高置信）
    灵隐寺（2篇提到）
    雷峰塔（1篇提到）
  → 按提及次数降序展示
```

### 场景 4：多轮规划不"失忆"（S8）

```
用户："帮我规划杭州三天行程"
Agent：生成 Day1-3 行程
用户："把 Day2 换成自然风光"
Agent：只修改 Day2，Day1 和 Day3 保持不变（不再重复选已规划景点）
```

## 3. V2 需求清单（按里程碑）

### 里程碑 A：能力扩展 — 搜索抓取

| ID | 需求 | 用户感知 |
|----|------|---------|
| A1 | 用户在聊天中可用自然语言搜索攻略 | "搜杭州三日攻略" |
| A2 | 搜索结果以链接列表呈现，用户确认后再抓取 | 看到链接，选择要抓哪些 |
| A3 | 抓取结果自动传入 guide_parser 解析 | 无缝衔接现有流程 |
| A4 | 保留手动粘贴攻略入口，两种方式共存 | 粘贴框 + 搜索框都在 |

### 里程碑 B：数据质量 — 解析增强

| ID | 需求 | 用户感知 |
|----|------|---------|
| B1 | 攻略解析输出游玩时长（`suggested_duration_h`） | 看到"建议玩 3.5 小时" |
| B2 | 攻略解析输出最佳时段（`best_time`） | 看到"早晨去人少" |
| B3 | 攻略解析谨慎输出费用（`cost_estimate`，仅在有明确原文依据时） | 看到"门票 60"（有依据时） |
| B4 | 多源合并去重，按提及次数排序 | 看到"西湖（3 篇提到）" |
| B5 | 行程节点标注攻略来源 | 看到 POI 来自哪篇攻略 |

### 里程碑 C：能力扩展 — 事实核验升级

| ID | 需求 | 用户感知 |
|----|------|---------|
| C1 | fact_checker 可通过搜索核实开放时间/门票等信息 | 天气/开放时间"能查官网确认" |

### 里程碑 D：记忆系统升级

| ID | 需求 | 用户感知 |
|----|------|---------|
| D1 | Agent 多轮规划时不重复选已规划景点 | 改 Day2 不影响 Day1/3 |
| D2 | 上下文自动修剪，防止 token 膨胀 | 无直接感知，但长对话不降质 |
| D3 | 规则放 system_prompt，当前状态从 DB 读取注入 | 无直接感知 |

### 里程碑 E：远期

| ID | 需求 | 用户感知 |
|----|------|---------|
| E1 | 用户画像：跨行程偏好学习 | 第二次用"记住我喜欢自然风光" |

## 4. V2 明确不做

- 多人协作（V1 已明确不做）
- 订票下单、社交、社区、UGC
- 图片攻略解析（需多模态 LLM，远期）
- Supervisor 的上下文修剪（先只做 itinerary_gen）
- 统一的 MCP 缓存/熔断/审计（出现需要时再升级）

---

## 5. V2 与 V1 的关系

V2 是 V1 的**增强迭代**，不是重写：

- 保留 V1 全部功能和 API 端点
- 新增 MCP 搜索入口，与手动粘贴共存
- guide_parser / itinerary_gen / fact_checker 内部升级，Tool 接口不变
- 新增 DB 字段和迁移，向后兼容

---

## 6. 成功标准

1. 能稳定演示"搜索攻略 → 抓取 → 解析 → 勾选 → 生成行程"完整闭环
2. 攻略解析结果包含时长、时段、费用（有依据时）三个新字段
3. 多源攻略能合并去重，展示提及次数
4. 多轮规划时 Agent 不选重复景点
5. V1 已有功能不受影响（回归）
