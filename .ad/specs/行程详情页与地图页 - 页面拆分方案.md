## 一、要解决的问题

**第一刀（已完成）：** 编辑和回顾挤在同一页 → 拆成行程页 + 全宽地图页。

**现在的缺口：** 地图页钉的仍是**计划节点**。用户没按行程走、去了计划外的地方时，照片挂不上节点，大量进待确认。归档模块被规定「不自动往行程里加点」，所以表现为「AI 没用」——其实是**不允许发明地点**。

**v2 要分开两份真源：**

| 真源 | 谁写 | 谁读 |
|------|------|------|
| **计划行程** | 生成 Job、用户编辑、Trip Assistant | 行程 Tab、规划路线图、聊天改行程 |
| **实际到访** | 照片 GPS 聚类 + 用户确认 | 回忆 Tab、实际停留钉、计划外照片墙 |

不是两份都能增删改排的 Day 列表。计划被回忆覆盖的话，重算路和聊天都会乱。

## 二、信息架构

### 2.1 Tab（只要两个）

| Tab 文案 | 路由 | 定位 | 核心内容 |
|----------|------|------|----------|
| **行程** | `/trips/:tripId` | 制定与整理 | Day 列表、编辑、规划路线图、批量上传、待确认、节点徽章 |
| **回忆** | `/trips/:tripId/map` | 真实足迹 | 全宽地图：计划点淡底 + 已确认实际停留实心钉；抽屉照片墙；灯箱 |

去掉灰掉的「照片」Tab。上传和待确认留在**行程**（整理场景）；看图和足迹留在**回忆**。

路由可以继续用 `/map`，不必再拆 `/recall`。对用户只显示「回忆」。

### 2.2 场景

| 场景 | 去哪 |
|------|------|
| 出发前改计划、旅行中微调节点 | 行程 |
| 回来批量上传、改挂到已有计划点 | 行程 |
| 确认「这批照片是计划外的新地点」 | 行程待确认 → 写入实际到访；回忆页能看见新钉 |
| 想看这次真正去了哪 | 回忆 |
| 想对比计划 vs 实际 | 回忆（计划淡底，实际实心） |

### 2.3 空态

回忆页还没有带 GPS 的照片、也没有已确认实际停留时：

- 仍可显示计划节点作**淡底**（虚线 / 低对比）
- 文案：「这是计划路线，还不是足迹。在行程页上传带地点的照片后，这里会长出实际停留。」

## 三、产品原则

1. **计划行程不被照片改写。** 不按拍摄顺序重排 `itinerary_items`，不删「没去的点」。没去的点只是回忆里没有实心钉。
2. **地点用计算，不用模型瞎猜。** GPS → 聚类 → 高德逆地理得到地名；LLM 最多给已有坐标写一句展示名，不负责「这张在哪」。
3. **计划外必须人确认。** 聚类只提出「建议停留」；用户点「这批就是这里」之后才变成实心关卡。
4. **一张原图。** 计划节点和实际停留都通过关联表指向同一个 `photo_id`。
5. **微信无 EXIF 图**仍不能自动变地点；可挂到已确认停留或计划节点，或等邻图带动（低置信，仍确认）。

## 四、数据口径（v2 要加的，尚未建表）

现有：`photo_assets`、`photo_assignments.item_id` → 计划节点。

新增（见执行计划 PC2）：

```
visit_stops          一次行程上的实际停留（建议 / 已确认）
  ├── trip_id
  ├── lat / lng          簇中心，GCJ-02
  ├── place_name         逆地理或用户改过的名字
  ├── linked_item_id     可空：离某计划节点足够近则挂上，不另开钉
  ├── status             suggested | confirmed | dismissed
  └── time_range         簇内拍摄时间最小/最大

photo_assignments
  ├── item_id            可空，计划节点
  └── visit_stop_id      可空，实际停留
```

匹配规则：

- 离某计划节点 ≤ 匹配半径（建议复用 2km 衰减，确认阈值另定）→ 只挂 `item_id`，**不**再建 `visit_stops`。
- 否则生成 `suggested` 停留，待确认列表按**簇**展示，一次确认一簇。
- 用户确认后 `status=confirmed`；回忆地图只把 confirmed（以及已挂上的计划节点）画成实心钉。
- 计划节点顺序仍用 `seq` + `route_polyline`；实际连线按簇的时间中点排序，**另画一层**，不覆盖规划折线。

## 五、页面结构（已落地 + v2 差异）

### 5.1 行程 `/trips/:tripId`（已有，v2 文案微调）

```
顶栏：[行程] [回忆]
规划路线图（高德，序号 Marker + 折线）
Day 列表 + 节点卡片（PhotoBadge）+ 上传到这里
底部：批量上传 + 待确认
  v2：待确认增加「建议停留」分组（一簇多张 → 确认新地点 / 改挂到已有节点 / 忽略）
```

聊天、编辑、重算路只在这里。

### 5.2 回忆 `/trips/:tripId/map`（已有壳，v2 换数据）

```
全宽地图
  计划层：淡 Marker + 已有 route_polyline（可关）
  实际层：confirmed 停留 / 已归档计划点，按拍摄时间连线
点钉 → 抽屉照片墙 → 灯箱
只读：不上传、不在回忆页改计划节点
v2 允许：确认建议停留、忽略建议（与行程页待确认同一 API）
```
