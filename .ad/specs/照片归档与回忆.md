## 1. 这是什么

挂在现有旅行规划上的模块，不是新的规划 Agent。

旅行结束后（或行程已规划好），用户批量上传照片。系统用 **GPS + 拍摄时间** 挂到计划节点；挂不上的用 **聚类 + 逆地理** 提出「建议停留」，人确认后记成 **实际到访**。回忆页看足迹，行程页继续改计划。

| 真源 | 谁写 | 谁读 |
|------|------|------|
| **行程**（计划） | 生成 Job、用户编辑、Trip Assistant | 行程 Tab、规划图、聊天改行程 |
| **实际到访** | 照片 GPS 聚类 + 用户确认 | 回忆 Tab、实际停留钉 |

不是两份都能增删改排的 Day 列表。计划被回忆覆盖的话，重算路和聊天都会乱。

目标用户：20–35 岁自由行；无登录，照片挂在那一次 `trip_id` 上。

### 1.1 问题：行程和回忆会不会割裂？

会有一点，但**不该合成一个页面**。

长沙演示最能说明：计划是「2026-09-12 的一天」，照片是 2024-08-02～06。回忆若按计划 Day 1 套照片会丢图；按照片改计划，排路和助手会乱。两套时间轴是对的。

现在显得裂，是因为交互还按两个工具在用：上传/确认在行程，浏览在回忆；顶栏一个叫 Day 1、一个叫 8月2日；出发前回忆是空的，回来后行程又像后台。这是**阶段割裂**，不是信息架构错了。

**定位（一句话）：** 同一趟旅行——出门前编计划，回来后翻足迹。计划不被照片改写；回忆按拍摄时间和关键地点浏览。

不是「行程 App + 相册 App」，也不是「真实行程编辑器」（不要第二份可编辑 Day 列表）。

| | 行程 | 回忆 |
|--|------|------|
| 用户在干什么 | 决定去哪、怎么走 | 看自己去过哪、拍了什么 |
| 时间轴 | 计划日 | 拍摄日 |
| 地点 | 计划节点 | 同一批节点上的照片 + 确认过的计划外停留 |
| 能不能改计划 | 能 | 不能 |
| 空态 | 还没生成 | 计划作淡底：「还不是足迹」 |

三条钉死：

1. **同一次旅行。** Tab 只叫「行程 / 回忆」，不叫地图、照片。
2. **同一批地点，两种身份。** 岳麓山在行程里是计划节点，在回忆里是某拍摄日的关卡；应对着同一个 `item_id`，不是两个同名文件夹。
3. **一条主路径。** 出发前默认行程；有照片之后回忆不再是附属。上传和计划外确认仍在行程（写 `visit_stops`，不改计划）。回忆里点开照片就能改挂 / 拿掉 / 删除；行程节点提供「在回忆中看」。

刻意不做：按拍摄顺序重排计划、回忆里增删 Day、把未确认推断钉成关卡。

## 2. 原则

1. **地点用计算，不用模型瞎猜。** 有 GPS：距离 + 时间打分。计划外：聚类 + 高德逆地理。LLM 不负责「这张在哪」。
2. **计划不被照片改写。** 不按拍摄顺序重排 `itinerary_items`，不删「没去的点」。没去的点只是回忆里没有实心钉。
3. **计划外必须人确认。** 聚类只提出建议；确认后才成实心钉。
4. **一张原图。** 计划节点和实际停留都通过关联表指向同一个 `photo_id`。地图和照片墙用缩略图/预览图。
5. **微信无 EXIF 图**不能自动变地点；可改挂、从节点「上传到这里」，或等邻图带动（低置信，仍确认）。**禁止**用文件下载时间当游玩时间。
6. **批量是 Job，对话改归属才是 Agent。** 不做 `PhotoOrganizerGraph` / 四个视觉 Graph。

三不做：不生成行程、不重新排路、不静默往计划里加点。

## 3. 页面：行程 | 回忆

只要两个 Tab。路由 `/map` 不必改成 `/recall`。

| Tab | 路由 | 做什么 |
|-----|------|--------|
| **行程** | `/trips/:tripId` | 改计划、规划图、批量上传、建议停留、待确认、节点徽章 |
| **回忆** | `/trips/:tripId/map` | 全宽地图 + 底部抽屉。抽屉先展示当天「Day + 地点」节点脊，点节点后地图聚焦并切入该点照片墙。点开照片可改挂 / 拿掉 / 删除；不改计划节点 |

| 场景 | 去哪 |
|------|------|
| 出发前改计划 | 行程 |
| 回来上传、改挂到已有计划点 | 行程批量上传；或回忆里点开照片改挂 |
| 挂错了：换地点 / 拿掉 / 删图 | 回忆或行程里点开那张照片。只动照片归属，不改计划 |
| 确认「这批是计划外新地点」 | 行程「建议停留」→ 回忆长钉 / 脊上悬空珠 |
| 按时间翻关键地点、看照片 | 回忆抽屉的节点脊 |
| 看这次真正去了哪 / 计划 vs 实际 | 回忆地图 |

回忆空态（还没有带 GPS 的照片、也没有已确认停留）：计划节点作淡底，文案：「这是计划路线，还不是足迹。在行程页上传带地点的照片后，这里会长出实际停留。」

### 3.1 一张索引，不是两个产品

用户说的「章节 + 关卡」和「只按时间先后 + 关键地点排序」是**同一件事**：

- **章节** = **拍摄日**（`captured_at` 的日历日）。计划里的 Day 1 / 日期留在行程 Tab，回忆不拿计划日去套照片。
- 拍摄日跨了好几天：回忆顶栏按拍摄日切章（例如 8月2日 / 8月3日），不把几天揉进计划的「Day 1」。
- 拍摄日不在行程 `start_date～end_date` 里：仍然单独成章，照片不丢。
- 午夜跨天按日历切开（22:00 和次日 01:00 是两章），不把「当晚」强行并成一天。
- **关卡 / 关键地点** = 这一拍摄日有照片的计划节点，以及这一天确认过的计划外停留
- **排序** = 当天时间先后；同一地点内按 `captured_at`

地图是这张索引的空间投影；抽屉节点脊是线性投影。不要再做第三个「纯相册 App」。

```
一次行程（回忆）
  └── 拍摄日（章节，按日历排序）
        ├── 路线脊上的珠 = 这一天拍到过的计划内地点
        ├── 脊上/下方悬空的珠 = 这一天确认的计划外停留
        ├── 两珠之间的「空档」= 有拍摄时间、还没有地点的照片
        └── 末尾「未归类 · 无日期」= 没有拍摄时间也没有地点（仅最后一章）
```

### 3.2 回忆抽屉（目标交互，PD1）

主视图始终是地图：节点钉带缩略图，计划折线可关。

底部抽屉像系统控制中心：收起则地图独占；上划或点手柄拉开。只有两态：

1. **节点脊：** 当天 Day 标题 + 一条关卡线。计划内沿轴线；计划外悬空。点任意珠 → 地图聚焦该钉，抽屉切到照片墙。
2. **照片墙：** 该节点下的图；点图进灯箱。返回则回到节点脊。

地图点钉与抽屉点珠共用同一个焦点。路线折线可隐藏，钉仍可点。没照片的计划点可以淡显示，但**不从计划里删掉**。已确认的计划外停留（`visit_stops`）可在回忆抽屉「去掉这个停留」，或行程页「计划外停留」里去掉。有照片也能去掉：照片回到未归类，**不改计划**。

其他拍摄日的实际停留用**半透明小钉**叠在地图上（计划点天蓝、计划外琥珀），不按天换一套颜色。开关「显示其他拍摄日」默认开；关掉后只剩当天实心钉。点淡钉会切到那一天并打开该点照片。当天已有实心钉的地点不再叠一层淡钉。**视野：** 点拍摄日只框当天实心钉；勾选或再次点「显示其他拍摄日」才把其他天纳入同一视野。两地相距很远时，不要一换天就把地图缩到看见所有淡钉。

### 3.3 说不清的照片：插入「空档」，不发明地点

「插到路程合适的地方」分成两步，不要合成一步聪明算法。

| 照片情况 | 在索引里出现的位置 | 会不会写成地点 |
|----------|--------------------|----------------|
| 已挂计划点 / 已确认停留 | 在对应那颗珠下面 | 已有地点 |
| 有拍摄时间、没有地点（类型 B） | 按拍摄时间插在两颗已定点珠之间的「空档」（有地点时）；当天没有任何定点则仍是一颗「未归类」 | **否** |
| 没有时间也没有地点（类型 C） | 行程级「未归类」；邻图最多给出候选（PC4），在行程页确认 | **否**。确认前不进回忆实心钉 |

禁止：用 `mmexport` / 文件时间当拍摄时间；LLM 看图猜点；把未确认的推断钉成关卡。

PC4（同批邻图）是给类型 C 减待确认负担的，在**行程页**确认。回忆页只展示已经有地点的珠，外加诚实的「空档 / 未归类」。几天后才单独另存的微信包没有 GPS 邻居，邻图帮不上，只能人指定地点或留在「未归类 · 无日期」。**不写**下载时间当 `captured_at`。

### 3.4 视觉认地标：以后可选，不能当 PC4 主路径

微信图暂时只靠：人「上传到这里」/ 待确认改挂 / 同批邻图抄地点。这是当前能诚实做到的上限。

以后若做视觉认地标（暂记 **PV1**），必须同时满足，否则不准开：

1. **只在约束候选里选**（当天计划节点，或邻图已经给出的地点），禁止全国/全库乱认。  
2. **默认可关**；关了以后路径与现在完全一样。  
3. **低置信仍进待确认**，不得 `is_confirmed=true`，不得写成 confirmed 停留。  
4. **单独验收**，不和攻略图片解析、PC4 邻图混在一次上线里。  
5. **按张计费要可关**：一批上百张默认不跑视觉。

PV1 未做之前，PC4 代码里不准调用多模态。

## 4. 照片怎么走

```
上传 JPEG/PNG/WebP（拒 HEIC）
  → 只读 EXIF 的 GPS / DateTimeOriginal（不用下载时间）
  → 有 GPS：WGS-84→GCJ-02，和计划节点打分
       高置信自动挂 item_id；中置信挂上待确认；挂不上 → 聚类
  → 聚类中心逆地理 → 建议停留（可改挂计划点 / 确认新地点 / 忽略）
  → 无 GPS 有时间：当天候选，不自动定论
  → 微信类（无 GPS 无时间）：待确认；同批若夹在已定位原图之间，邻图抄地点（分数 ≤0.55，仍确认）
```

打分（改阈值必须改测试和开发实录）：

`Score = 0.50 × GPS + 0.30 × 时间 + 0.20 × 是否当天`  
自动归档 ≥ 0.85；0.60–0.85 待确认。GPS 衰减到 2km 为 0。聚类半径约 500m。

三类照片：A 有 GPS；B 无 GPS 有拍摄时间；C 两者都没有。

## 5. 已落地 vs 明确不做

**已落地（PA1–PA7、PC1–PC4、PD1–PD4、对话改归属）：** 上传去重、EXIF、打分挂节点、photo_jobs、行程/回忆拆分、建议停留、`visit_stops`、回忆双层地图、回忆抽屉拍摄日节点脊、行程/回忆互链文案、同批邻图带动无 EXIF（仍确认）、类型 B 空档条、带照片的计划外停留可去掉、助手提议改挂/去掉停留（人点采纳，不猜 GPS）、回忆页回放足迹与灯箱当天连翻。

**现在不做 / 先不做：**

| 不做 | 原因 |
|------|------|
| LLM 猜拍摄地；视觉认地标当主路径 | 地点是计算；PV1 只许在约束候选里选，见 §3.4 |
| YOLO 当身份分类器 | 人物身份必须用户命名 |
| 第二份可编辑「真实行程」 | 和计划抢真源 |
| 独立「按时间排序的相册」页面 | 就是回忆抽屉的节点脊，不另开 |
| 自动把类型 B/C 插进某个关卡并确认 | 只允许显示在空档 / 未归类 |
| 用拍摄时间把钉连成「实际路线」 | 没有真实轨迹，连线会误导 |
| 再做一层「计划去了 / 照片里没有」的对照皮肤 | 淡钉已经够用 |
| 登录 / `user_id` | 照片挂 `trip_id` |
| Redis / Celery / S3 | 本机 `uploads/` + 同进程 Worker 够演示 |
| 游记 | 另开需求 | 用照片顺序覆盖计划 `seq` |
| 人物检测 PB1 | 等照片墙稳定再用预训练 `person` |

## 6. 数据（口径）

`photo_assets`：一行一文件（原图 + 预览 + 缩略图 + hash + EXIF GPS/时间）。  
`photo_assignments`：主归属一张一主；`item_id` 和 `visit_stop_id` 可空。  
`photo_jobs`：一批上传，不复用 `generation_jobs`。  
`visit_stops`：簇中心 GCJ-02、建议地名、`suggested | confirmed | dismissed`；近计划点可填 `linked_item_id`，不另开钉。

匹配：高置信只写 `item_id`；否则建议停留。回忆地图只画 confirmed 停留和已归档计划点。**不**按拍摄时间另画实际折线（没有真实轨迹）。计划折线仅作可开关对照，不覆盖 `seq` / `route_polyline`。

删计划节点：assignment 的 `item_id` SET NULL，原图还在。

## 7. 以后：人物（未做）

挂在归档之上，不是新的旅行规划产品。

- YOLO **只检测** `person` 框，不把人分成「我/妈妈」类别。身份 = 向量聚类 + 用户给组起名。
- 人物档案挂在**这一次行程**，不建账号级社交图。共同出镜不自动写成「家人」。
- 原图仍只一份；`photo_persons` 存 `photo_id` + bbox + 人物 id。
- 人脸特征高敏感：默认可关；不长期存无必要的人脸裁剪。
- 批量检测是 Service/`photo_jobs` 阶段，不是四个 LangGraph。对话只负责「这张是妈妈」「改到拙政园」。

顺序：照片墙能用（已完成）→ PB1 框 + 手动画名 → PB2 聚类命名 → PB3 行程内关系。没有失败案例和授权数据之前，不训练自定义 YOLO。

## 8. 验收愿望（产品，不是 CI 断言「挂对了」）

自动化用合成坐标：近且时间对 → ≥0.85；无 GPS 不自动挂；微信图 `captured_at` 空；hash 去重；坐标转换。  
真机：一批带 GPS 的图多数落到计划点或建议停留；确认后回忆页长钉；计划节点列表不变。
