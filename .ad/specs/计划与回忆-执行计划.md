## 目标

用户没按计划走时，计划外照片不再只能一张张改挂。系统用 GPS 聚类 + 高德逆地理提出「建议停留」，用户确认后写入**实际到访**；回忆地图长出实心钉。

**不改写计划行程。** 不按拍摄顺序重排 `itinerary_items`，不把「没去的点」从计划里删掉。

---

## 原则（每阶段都遵守）

| 必须 | 禁止 |
|------|------|
| 地点用 GPS / 聚类 / 逆地理，可单测 | LLM 猜「这张在哪」 |
| 计划外地点必须人确认后才成实心钉 | 静默往 `itinerary_items` 加点 |
| 一张原图；关联表指向 `item_id` 或 `visit_stop_id` | 复制 JPEG、第二份可编辑 Day 列表 |
| 回忆页计划层只做淡底 | 用照片顺序覆盖 `seq` / `route_polyline` |

## 数据（PC2 建，PC1 不改库）

```
visit_stops
  id, trip_id
  lat, lng                 簇中心，GCJ-02
  place_name               逆地理或用户改名
  linked_item_id           可空；离计划节点够近则挂上，不另开钉
  status                   suggested | confirmed | dismissed
  time_start, time_end     簇内拍摄时间
  evidence_json            半径、张数、逆地理原文、规则名
  created_at, updated_at

photo_assignments
  现有 item_id（可空）
  + visit_stop_id（可空）
  主归属仍一张一主；计划点和实际停留二选一或同时挂（近计划点时只写 item_id）
```

匹配口径（PC2 写进 `photo_match` 旁的新模块，例如 `photo_cluster.py`）：

1. 有 GPS 的照片先走现有节点打分。高置信 → 只写 `item_id`，**不**建 `visit_stops`。
2. 未挂上计划点的 GPS 点：按距离聚类（建议 DBSCAN 或固定半径，半径与匹配衰减同量级，约 2km 内再调；单测用合成点）。
3. 每簇取中心 → 高德逆地理 `regeo`（新建，仓库里目前只有正向 `geocode_poi`）→ `place_name` 建议。
4. 簇中心离某计划节点仍很近 → 填 `linked_item_id`，UI 提示「可能就是计划里的 X」，确认则改挂节点而不是新停留。
5. 否则 `status=suggested`，待确认按簇展示。
6. 用户确认 → `confirmed`；忽略 → `dismissed`。回忆地图只画 confirmed，以及已归档的计划节点。

实际连线：按簇时间中点排序，**另画一层**，不覆盖规划折线。

| 文件 | 做什么 |
|------|--------|
| `src/frontend/src/pages/TripPage.tsx` | 「地图」→「回忆」；删掉灰掉的「照片」 |

**验收**

- 只有两个 Tab：行程、回忆。

- 上传、待确认、节点徽章仍在行程页。
- `npx tsc -b`；浏览器点两个 Tab 来回。

**不做：** 建表、聚类、改匹配阈值。

## PC2 — 聚类、逆地理、按簇确认

**改哪些文件（预估）**

| 文件 | 做什么 |
|------|--------|
| `alembic/versions/0019_visit_stops.py` | `visit_stops` + `photo_assignments.visit_stop_id` |
| `app/models/photo.py` | 模型 |
| `app/services/photo_cluster.py`（新） | 聚类；禁止 LLM |
| `app/agents/tools/geo.py` 或 `app/services/geo_regeo.py`（新） | 高德逆地理；走现有 `amap_cache` |
| `app/services/photo_pipeline.py` | 匹配失败后跑聚类 |
| `app/api/v1/photos.py` | 建议停留列表；确认 / 改挂计划点 / 忽略 |
| `app/schemas/photo.py` | 响应含簇 |
| `PhotoArchivePanel.tsx` | 待确认按簇分组 |
| 单测 `test_photo_cluster.py` | 合成点：近计划点不建停留；远点成一簇 |

**验收**

- pytest（`--noconftest`）：聚类半径、不改 `itinerary_items`、确认后 assignment 指向 `visit_stop_id`。
- 演示：武功山/长沙夹具里故意偏远的 GPS（或合成点）出现「建议停留」；确认后行程节点列表**不变**。
- 逆地理失败：仍给出「未命名停留」+ 坐标，不让模型编地名。

**不做：** 回忆地图双层（那是 PC3）；不训练视觉。

## PC3 — 回忆地图双层

**改哪些文件**

| 文件 | 做什么 |
|------|--------|
| `TripMap.tsx` `variant=recall` | 计划 Marker + 折线淡底（可关）；confirmed 停留实心钉 |
| 地图 summary API 或现有 photos summary | 返回计划点照片 + 实际停留照片 |
| `PhotoDrawer` | 钉可以是 `item_id` 或 `visit_stop_id` |

**验收**

- 只走了计划点：回忆页看起来仍像现在（实心计划钉），淡底可关。
- 确认过计划外停留：多一颗钉，点开是那一簇照片。
- 计划节点顺序、行程页编辑、重算路不受影响。

**不做：** 按时间播放轨迹、游记、对比「哪些计划点没去」的报表（以后可从「无实心钉的计划点」派生，不在本阶段做产品）。
