## PC4：同批邻图带动无 EXIF ✅

### 要解决什么

一批上传里经常混着手机原图（类型 A，有 GPS）和微信另存（类型 C，GPS 和时间都被剥光）。C 现在整批进待确认，人要一张张选地点。

邻图规则：**同一 `photo_job` 里，夹在已定位照片中间（或紧挨着）的类型 C，把邻居的地点抄过来当候选。** 分数封顶 0.55，永远待确认。地点仍然是计算抄来的，不是模型猜的。

典型路径：相册里连续选「金顶 GPS → 金顶 GPS → 微信转发 × 5 → 金顶 GPS」。五张微信图建议挂到金顶，用户点一次确认或批量改挂。

### 不做

| 不做 | 原因 |
|------|------|
| 写 `captured_at`（文件 mtime、`mmexport` 文件名里的数字） | 那是下载时间，会把整批挂到「今天」 |
| `is_confirmed=true` 或把停留写成 `confirmed` | 邻图只是提示 |
| 看别的 job / 整个行程里「多数图在哪」 | 跨天混传会把微信图绑错地方 |
| 类型 B（无 GPS、有拍摄时间） | B 已有当天候选；PC4 只补 C |
| 按文件名排序当邻接 | `IMG_` 和 `mmexport` 混排没有拍摄序；v1 只用上传顺序 |
| LLM / 看图认地标 | **不是 PC4 主路径。** 以后可选 PV1：只在当天候选里选、可关闭、低置信仍给人、单独验收。未做前代码里不准调多模态 |
| 新表、新路由、改计划节点 | 只改 assignment |

### 邻接怎么定义（推荐：连续段，不是固定窗口）

`photo_jobs.payload.photo_ids` 已是用户选文件的顺序（接近相册顺序）。**不要**改成按文件名排。

一张照片是 **锚点**，当且仅当：

- 有 GPS（类型 A），且
- 主归属已落到地点：`item_id` 有值（GPS 打分挂上），或 `visit_stop_id` 有值（PC2 聚类建议）

类型 C、失败、GPS 但哪儿都没挂上的 A，都不是锚点。

把 `photo_ids` 按上传顺序切成「锚点之间的 C 段」：

```
… 锚点L | C C C | 锚点R …
```

| 段的两边 | 行为 |
|----------|------|
| L 和 R 指向**同一**目标（同一个 `item_id`，或同一个 `visit_stop_id`） | 段内全部 C 抄该目标 |
| 只有一边有锚点（批头 / 批尾） | 段内全部 C 抄这一边 |
| L 和 R 指向**不同**目标 | **整段不抄**（走在两个景点之间，不猜） |
| 整批没有锚点 | 什么都不做（纯微信包仍待确认） |

固定 ±2 张窗口不采用：微信转发经常连续 5～8 张，中间几张会看不到 GPS 邻居。

目标键必须同类相比：`(item_id, None)` 与 `(None, visit_stop_id)` 视为不同。不要把「计划里的拙政园」和「聚类出来的未命名停留」当成同一个地方。

### 写库口径

在 `process_photo_job` 里：**每张 `process_photo_asset` → `suggest_visit_stops` → `apply_batch_neighbors`。** 必须在聚类之后，C 才能抄到建议停留。

对命中的每张 C：

- `assignment_type = batch_neighbor`
- `confidence = 0.55`（三明治）或 `0.50`（只有一边）；**上限 0.55**，低于自动线 0.85，也低于「挂上待确认」线 0.60
- `is_confirmed = false`
- 抄 `item_id` **或** `visit_stop_id`（只抄锚点已有的那一个，另一个保持空）
- **不写** `captured_at` / lat / lng
- `evidence_json`：

```json
{
  "photo_class": "C",
  "rule": "batch_neighbor",
  "bound": "sandwich | left | right",
  "confidence_cap": 0.55,
  "neighbor_photo_ids": ["锚点uuid…"],
  "target_kind": "item | visit_stop",
  "poi_name": "金顶"
}
```

已有 `item_id` / `visit_stop_id` 的照片不要覆盖（含用户「上传到这里」的 manual）。

现有确认逻辑不用改：

- 待确认里 `item_id` + `confidence < 0.85` 本来就会列出（下拉框已会预选建议节点）
- 抄到 `visit_stop_id` 的 C 会进「建议停留」卡片（`photo_count` 按 assignment 现算）
- 确认 / 改挂 / 忽略停留已经会带动该停留上全部 assignment
